## Topic: Borrowing rules and API client

**Me:** I wrote a `validateBorrowRequest()` function and a `createBorrowRequest()` function. Based on my friend's database README, is there anything I need to fix?

**AI:** The code should follow the database naming conventions, check whether the book is available, prevent users from borrowing their own books, and account for locked users. The borrower ID should come from the authenticated session on the backend rather than being trusted from the frontend.

**Me:** I don't check if the book already has a pending request since I allow multiple requests.

**AI:** Multiple users can submit pending requests for the same book. However, the same user cannot have two pending requests for the same book. The backend should enforce this rule, so frontend validation does not necessarily need to duplicate it.

**Me:** Do I have to check whether the same person submitted two pending requests, or does the API just return failed and my code already handles that?

**AI:** The frontend can rely on the API to reject duplicate requests, provided the backend implements the rule. The existing `data.js` throws an `ApiError` when the HTTP response is unsuccessful, allowing the calling function to handle the error with `try/catch`.

**Me:** I don't understand whether the code inside `try` will always return success.

**AI:** JavaScript executes the success return only if it reaches that statement. If `createBorrowRequest()` throws an error, execution skips the remaining statements in `try` and moves to `catch`. The function then returns `success: false`.

**Me:** Where does my friend's code throw the error?

**AI:** In `src/data/data.js`, the `request()` helper checks `response.ok`. When the HTTP response is unsuccessful, it executes `throw new ApiError(...)`. That error propagates through `createBorrowRequest()` to the calling function's `catch` block.

**Me:** My friend also has an `app.js`. What does it do?

**AI:** `app.js` handles the frontend interactions: loading available books, displaying book cards, attaching click handlers to Borrow buttons, and showing success or error messages. `data.js` provides reusable API-calling functions. The backend implementation is a separate part of the system.
